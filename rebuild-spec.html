1. Overview

Rebuild the 10 existing flows as 6 Copilot Studio workflows (Microsoft Copilot harness) that process only changed files and produce one HTML report per line of business (LOB). The requirement is unchanged; only the mechanics change.

Why the current build fails. Every run scans the whole site, and the report is generated from retrieval (RAG). Retrieval returns only the top few chunks, so a report over hundreds of folders is incomplete by design and varies run to run. Full scans also hit the 100-second agent limit, connector throttling (600 calls/min for SharePoint) and model context limits.

Target design in four rules

  1. Per-LOB isolation. Each LOB is processed by its own child run with its own watermark. One LOB failing never blocks the others.
  2. Incremental only. Each run lists only files modified since that LOB's last successful run.
  3. Summarize once, store forever. Each file is summarized once into Dataverse; it is re-summarized only when its ETag changes.
  4. AI never writes HTML. Reports are assembled from stored summaries with deterministic expressions and a fixed template.

Assumed folder structure (adjust paths to yours):

Shared Documents/
  <LOB>/                 <- one report per LOB
    <Area>/              <- level-2 folder = report section
      <Sub-area>/.../file  <- any depth, shown as a breadcrumb

Output: Reports/<LOB>.aspx (or .html sent by Teams/Outlook), regenerated only when that LOB changed.

4. WF0 – Orchestrator (scheduled)

WF0 does no work itself: it fans out one child run per enabled LOB and never overlaps with its previous run.

  1. Trigger: Recurrence, every 30 minutes (Settings → Concurrency control On, degree 1, so a slow run is never doubled up).
  2. Dataverse – List rows LOB Config, Filter rpt_enabled eq true, Select columns rpt_lobconfigid,rpt_name.
  3. Apply to each LOB row (Settings → Concurrency 3; raise to 5 once stable).
    1. Run a child workflow → WF1 – Process LOB, input LobId = items('Apply_to_each')?['rpt_lobconfigid'].
    2. Configure run after on the next step = is successful, has failed, has timed out, so one LOB failure does not stop the loop.
  4. Compose RunSummary (optional): count of LOBs processed, for a Teams alert if any child failed.

Keep WF0 this thin. All logic, error handling and the watermark live in WF1, per LOB.

5. WF1 – Process LOB (child)

WF1 replaces the full scan: it lists only files modified in this LOB since its watermark, queues them, then runs summarize, roll-up and render for that LOB alone.

Trigger: When a workflow is called by another workflow (child), input LobId (text).

Init

  1. Dataverse – Get a row by ID LOB Config = LobId.
  2. Compose RunStart = utcNow().
  3. Compose Since = formatDateTime(addMinutes(outputs('Get_LOB')?['body/rpt_lastsuccessfulrunutc'], -10), 'yyyy-MM-ddTHH:mm:ssZ') (10-min overlap; ETag check removes duplicates).

Scope Try

  1. SharePoint – Get files (properties only)
    • Library: Documents
    • Limit entries to folder: @{outputs('Get_LOB')?['body/rpt_folderpath']}
    • Include nested items: Yes
    • Filter Query: Modified ge '@{outputs('Since')}' and FSObjType eq 0 (files only; if FSObjType is rejected, drop it and add a Filter array on {IsFolder} = false)
    • Settings → Pagination On, threshold 20000
  2. Apply to each file (Concurrency 10). Inside:
    1. Compose Parts = split(item()?['{Path}'], '/')
    2. Compose Area = if(greater(length(outputs('Parts')), 3), outputs('Parts')[2], 'General')
    3. Compose Breadcrumb = join(take(skip(outputs('Parts'), 3), max(0, sub(length(outputs('Parts')), 4))), ' / ')
    4. Dataverse – List rows DocCatalog, Filter rpt_spitemid eq @{item()?['ID']}, Row count 1.
    5. Condition empty(outputs('List_existing')?['body/value'])
      • Yes → Add a new row: SpItemId, LOB, Area, Breadcrumb, FileName {Name}, FileUrl {Link}, ETag @odata.etag, ModifiedUtc, ModifiedBy, Status Pending, Attempts 0.
      • No → Condition stored ETag ≠ item()?['@odata.etag'] → Update a row: same fields, Status Pending, Attempts 0. Equal ETag → do nothing.
  3. Select ChangedAreas from the Get files output: map each item to if(greater(length(split(item()?['{Path}'],'/')),3), split(item()?['{Path}'],'/')[2], 'General'), then Compose DistinctAreas = union(body('ChangedAreas'), body('ChangedAreas')).
  4. Apply to each area (Concurrency 1): upsert FolderSummary (LOB + Area) with Dirty = Yes.
  5. Condition greater(length(body('Get_files')?['value']), 0) → Update LOB Config ReportDirty = Yes.
  6. Dataverse – List rows DocCatalog, Filter _rpt_lob_value eq @{LobId} and rpt_status eq <Pending>, Sort rpt_modifiedutc asc, Row count = BatchSize.
  7. Apply to each pending row (Concurrency 5) → Run child workflow WF2 – Summarize file, input CatalogId.
  8. List rows FolderSummary where LOB = this LOB and Dirty = Yes → Apply to each (Concurrency 3) → Run child workflow WF3 – Roll up area.
  9. Get a row LOB Config again → Condition ReportDirty = Yes → Run child workflow WF4 – Render LOB report.
  10. Update LOB Config: LastSuccessfulRunUtc = outputs('RunStart').
  11. Add RunLog row, Outcome = Succeeded.

Scope Catch (run after Try has failed / timed out)

  1. Add RunLog row, Outcome = Failed, ErrorText = string(result('Try')). Do not move the watermark: the next run retries the same window.

One-time library settings

  • Library settings → Indexed columns → index Modified. Without it, the filtered query on a large library can fail on the 5,000-item list view threshold.
  • If your library name or root differs, shift the Parts index offsets (Area = index 2 assumes Library/LOB/Area/…).

6. WF2 – Summarize file (child)

WF2 turns one file into one small, validated JSON summary and records success or failure on its catalog row; it never touches HTML.

Trigger: child workflow, input CatalogId.

  1. Get a row by ID DocCatalog.
  2. Condition: supported type? extension in pdf, docx, pptx, xlsx, txt, md, and file size under your cap (start at 15 MB). No → Update row Status Skipped, Summary = File type not summarized, then stop. Skipped files still list in the report with name and link.
  3. SharePoint – Get file content (by ID/path from the row).
  4. Run a prompt (AI capabilities). Pass the file as a document input; for txt/md/xlsx pass extracted text cut to the first 30,000 characters with substring(text, 0, min(length(text), 30000)).
  5. Parse JSON on the prompt output using the schema below.
  6. Update row: Status Summarized, Summary = body('Parse_JSON')?['summary'], SummaryJson = full output, LastError empty.
  7. Scope Catch (run after 3–6 failed / timed out): Attempts + 1; Status = if(greaterOrEquals(add(Attempts,1),3),'Failed','Pending'); LastError = error message. A Pending row is retried on the next run; after 3 tries it stays Failed and shows in the report banner.

Settings: retry policy Exponential, 4 retries on Get file content and Run a prompt (absorbs 429 throttling).

Prompt instructions (paste into the prompt node)

You summarize one document from the {LOB} line of business for a status report.
Use only the document. If something is not stated, return an empty string or empty list.
Return ONLY valid JSON matching the schema. No markdown, no HTML, no commentary.
summary: at most 80 words, plain language, what the document is and its main point.
key_points: at most 5 items, each under 20 words.
actions_or_risks: open actions, deadlines or risks stated in the document.

File: {FileName}  |  Folder: {Area} / {Breadcrumb}  |  Modified: {ModifiedUtc}
Document: {document input or text}

Output JSON schema (set as the prompt's JSON output and in Parse JSON)

{
  "type": "object",
  "properties": {
    "title":              { "type": "string" },
    "doc_type":           { "type": "string", "enum": ["report","procedure","minutes","plan","data","other"] },
    "summary":            { "type": "string" },
    "key_points":         { "type": "array", "items": { "type": "string" } },
    "owner":              { "type": "string" },
    "decision_or_status": { "type": "string" },
    "actions_or_risks":   { "type": "array", "items": { "type": "string" } }
  },
  "required": ["title","doc_type","summary","key_points"]
}

Use a prompt node, not an agent node: one file needs no tools or reasoning loop, and the prompt is cheaper, faster and more consistent.

7. WF3 – Roll up area (child)

WF3 writes the section overview for one Area from its stored file summaries only, never from raw files, so input size stays bounded however deep the sub-folders go.

Trigger: child workflow, input FolderSummaryId.

  1. Get a row by ID FolderSummary (gives LOB + Area).
  2. List rows DocCatalog where LOB = this LOB, Area = this Area, Status = Summarized; Select columns rpt_filename, rpt_breadcrumb, rpt_modifiedutc, rpt_summary only; Sort rpt_modifiedutc desc; Pagination On.
  3. Select Lines → concat(item()?['rpt_breadcrumb'], ' | ', item()?['rpt_filename'], ' | ', formatDateTime(item()?['rpt_modifiedutc'],'yyyy-MM-dd'), ' | ', item()?['rpt_summary']).
  4. Condition lessOrEquals(length(body('Lines')), 60)
    • Yes → Run a prompt "Area roll-up" with join(body('Lines'), decodeUriComponent('%0A')).
    • No → batch: Apply to each over chunk(body('Lines'), 60) (Concurrency 1) → prompt each chunk → Append to array Partials → one final prompt over join(variables('Partials'), …).
  5. Parse JSON → Update row FolderSummary: Overview, ThemesJson, FileCount (all rows in Area), SummarizedCount, Dirty = No.

Roll-up prompt: "You are given one-line summaries of files in the {Area} area of {LOB}. Return ONLY JSON: overview (2–4 sentences), themes (≤5), recent_changes (≤5, newest first, cite file names), open_actions (≤5). Use only the lines given."

Run it only for Dirty areas (WF1 step 11), so an unchanged Area costs nothing.

8. WF4 – Render LOB report (child, no AI)

WF4 builds one complete, well-formed HTML file per LOB from Dataverse alone, using Select/Join and a fixed template; the output is identical in structure every run.

Trigger: child workflow, input LobId.

Escape rule. Wrap every text value you insert in this expression (written below as E(x)); unescaped &, < or quotes from file names and summaries are the usual cause of broken HTML:

replace(replace(replace(replace(coalesce(x,''),'&','&amp;'),'<','&lt;'),'>','&gt;'),'"','&quot;')

Steps

  1. Get a row LOB Config.
  2. List rows FolderSummary for this LOB, Sort rpt_area asc.
  3. List rows DocCatalog for this LOB, Status ≠ Deleted, Select only rpt_area, rpt_breadcrumb, rpt_filename, rpt_fileurl, rpt_modifiedutc, rpt_status, rpt_summary, Pagination On.
  4. Coverage counts: four Filter array actions on step 3 (Summarized, Pending, Failed, Skipped) → length(body('Filter_x')).
  5. Select Toc from step 2 → concat('<li><a href="#', <slug>, '">', E(item()?['rpt_area']), ' (', item()?['rpt_filecount'], ')</a></li>'), where <slug> = concat('a-', replace(uriComponent(toLower(item()?['rpt_area'])), '%', '-')).
  6. Initialize variable Sections (Array).
  7. Apply to each FolderSummary row – Settings → Concurrency OFF (1). Appending in parallel is what scrambles or drops sections.
    1. Filter array step 3 where rpt_area = current Area.
    2. Select FileRows → concat('<tr><td><a href="', item()?['rpt_fileurl'], '">', E(item()?['rpt_filename']), '</a></td><td>', E(item()?['rpt_breadcrumb']), '</td><td>', formatDateTime(item()?['rpt_modifiedutc'],'yyyy-MM-dd'), '</td><td>', E(item()?['rpt_summary']), '</td></tr>')
    3. Append to array Sections: concat('<section id="', <slug>, '"><h2>', E(area), '</h2><p class="ov">', E(overview), '</p><table><thead><tr><th>File</th><th>Folder</th><th>Modified</th><th>Summary</th></tr></thead><tbody>', join(body('FileRows'), ''), '</tbody></table></section>')
  8. Compose Html: paste the template below; it pulls in the counts, join(body('Toc'),'') and join(variables('Sections'),'').
  9. Save the file to Reports/<ReportFileName>: Get file metadata using path → exists ? Update file : Create file.
  10. Update LOB Config: ReportDirty = No, LastReportUtc = utcNow().

Template for Compose Html

<!DOCTYPE html>
<html lang="en"><head><meta charset="utf-8">
<title>@{E(LOB name)} – Content report</title>
<style>
body{font:14px/1.5 Segoe UI,Arial,sans-serif;margin:24px;color:#222}
.banner{background:#f3f6f9;border:1px solid #d0d7de;padding:12px 16px;border-radius:8px}
.warn{color:#b35900}
table{border-collapse:collapse;width:100%;margin:8px 0 24px}
th,td{border-bottom:1px solid #e5e7eb;padding:6px 8px;text-align:left;vertical-align:top}
th{background:#fafafa}
.ov{max-width:900px}
@media print{a{color:#000;text-decoration:none}}
</style></head><body>
<h1>@{E(LOB name)} – Content report</h1>
<div class="banner">Generated @{formatDateTime(utcNow(),'yyyy-MM-dd HH:mm')} UTC ·
 @{TotalFiles} files · @{Summarized} summarized · @{Pending} pending ·
 <span class="warn">@{Failed} failed</span> · @{Skipped} not summarizable</div>
<h2>Contents</h2><ul>@{join(body('Toc'),'')}</ul>
@{join(variables('Sections'),'')}
</body></html>

Where to publish so it opens in the browser. SharePoint Online forces .html files in libraries to download. Either save as .aspx using a connection owned by a site owner (a member-level connection still downloads), or send .html as a Teams/Outlook attachment from step 9. Choose one per LOB in ReportFileName.

9. Deletes, backfill and go-live

The delta query never sees deleted files, so a weekly reconcile keeps reports honest; the first run over existing content is a backlog that drains over several runs.

WF5 – Weekly reconcile (scheduled, Sunday night, per LOB)

  1. For each LOB: Get files (properties only) with no Modified filter, nested items Yes, pagination On; Select the IDs.
  2. List rows DocCatalog for the LOB, Status ≠ Deleted, Select rpt_spitemid only, pagination On.
  3. Filter array catalog rows where not(contains(body('SpIds'), item()?['rpt_spitemid'])) → Update row Status = Deleted; mark their Area Dirty and LOB ReportDirty = Yes.

Backfill (first run)

  • Seed every LOB's LastSuccessfulRunUtc with 1900-01-01: run 1 catalogs every file as Pending.
  • BatchSize caps summarizing per run, so the backlog drains over the next runs. The report banner shows the Pending count meanwhile.
  • To finish faster, run once overnight with BatchSize 500 and the WF1 step 10 concurrency at 10.

Solution and settings

  • One solution: all workflows, 4 tables, connection references (SharePoint, Dataverse) and environment variables for the site URL, library name and file-size cap.
  • Retry policy Exponential, 4 on every SharePoint and prompt action.
  • Every action consumes Copilot Credits; the incremental design and ETag check are what keep cost proportional to change, not to site size.
  • In the template, replace each E(…) shorthand with the full escape expression.

Test checklist before switching off the old 10 flows

  • One LOB enabled; backfill completes; banner totals match the file count in SharePoint for that LOB folder.
  • Edit one file → next run re-summarizes only that file; its Area section updates; others unchanged.
  • Add a file 4 levels deep → appears under the right Area with the correct breadcrumb.
  • A file named with & and < renders correctly (escape check).
  • Force a prompt failure (unsupported or corrupt file) → row goes Failed after 3 tries; banner shows it; report still renders.
  • Delete a file → gone from the report after the weekly reconcile.
  • Kill a run mid-way → watermark did not move; next run reprocesses the window.
  • Report opens in the browser (not downloaded) for a normal member account.
  • Enable the remaining LOBs one at a time.
