Build guide: LOB SharePoint HTML reports

Step-by-step instructions for building the six workflows in Copilot Studio · read the overview first (10 minutes)

How to use this guide: work through the parts in order. Each workflow section says what the workflow is for, then lists the actions to add, with the settings to type in and a short Why for each important step. Every part ends with a test. Don't start the next part until the test passes.

Why this build order? WF1 calls WF2, WF3 and WF4, and WF0 calls WF1. A workflow can only call another workflow that already exists, so we build the "inner" workflows first and work outwards.

Before you start

Check you have all of these. Ask your lead if anything is missing.

  • Maker access to the Power Platform environment where Copilot Studio runs (it must have Dataverse).
  • Edit access to the SharePoint site. For publishing reports as .aspx you'll also need a site owner account for the save step (see Part 4).
  • The library name (usually Documents, shown as "Shared Documents" in paths) and the list of LOB folder names.
  • Someone with library settings access has indexed the Modified column: Library settings → Indexed columns → Create a new index → Modified.
    Why: our query asks "files modified since X". On a library with more than 5,000 files, SharePoint refuses that query unless the column is indexed.
  • A solution created in the environment (e.g. "LOB Reports"). Create every table and workflow inside it.
    Why: a solution keeps all the parts together so they can be moved from dev to production as one package.

The folder layout this guide assumes

Shared Documents/              (the library)
  Transmission/                (a LOB  → gets its own report)
    Protection/                (an Area → a section in the report)
      Relays/2026/Q3/file.pdf  (deeper folders → shown as a breadcrumb "Relays / 2026 / Q3")

If your library is laid out differently, the only thing to change is the folder-position numbers in Part 5 (explained there).

Five things to know about expressions

Many steps ask you to type an expression (a small formula) into a field. If you haven't used them before, read this first.

  1. Where to type them: click in the field, open the expression editor (the fx button), paste the expression, and click Add/OK. Don't paste expressions as plain text, or they will be treated as text.
  2. Action names matter. An expression like outputs('Get_LOB') means "the output of the action named Get LOB". Spaces become underscores. Rename each action exactly as this guide says (click the action's title to rename it), or the expressions won't find it.
  3. ?['name'] reads a field. item()?['Name'] means "the Name field of the current item". The ? stops the workflow from crashing if the field is empty.
  4. item() means "the current row" inside a loop (Apply to each) or inside a Select / Filter array.
  5. Dataverse column names have a prefix. This guide uses rpt_ (e.g. rpt_status). Your environment's prefix may be different. Check the column's logical name in the table designer and replace rpt_ everywhere if needed.

Part 1 – Create the Dataverse tables

Goal: create the four tables the workflows read and write. Tables are like spreadsheets: each has columns, and each row is one record.

In your solution: New → Table. For each table below, add the columns listed. Column types are exactly as shown.

Table 1: LOB Config

One row per LOB. This is the "control panel": you switch LOBs on and off here without editing any workflow.

ColumnTypeWhat it's for
NameText (primary column)The LOB's display name, e.g. "Transmission"
FolderPathTextThe LOB's folder, e.g. Shared Documents/Transmission (no slash at the end)
EnabledYes/NoOnly LOBs set to Yes are processed
LastSuccessfulRunUtcDate and timeThe watermark: when this LOB last ran successfully. Set it to 1900-01-01 for a brand-new LOB so the first run picks up every file.
ReportDirtyYes/NoYes = something changed, so the report needs rebuilding
BatchSizeWhole numberMaximum files to summarize per run. Start with 100.
ReportFileNameTextName of the report file, e.g. Transmission.aspx
LastReportUtcDate and timeWhen the report was last built

Table 2: DocCatalog

One row per SharePoint file. This is our "card catalog".

ColumnTypeWhat it's for
FileNameText (primary column)The file's name
SpItemIdWhole numberSharePoint's ID for the file. We use it to find the row again.
LOBLookup → LOB ConfigWhich LOB the file belongs to
AreaTextThe area (report section) the file is in
BreadcrumbTextDeeper folders, e.g. Relays / 2026 / Q3
FileUrlURLLink to the file, shown in the report
ETagTextSharePoint's version tag. If it changes, the file changed.
ModifiedUtcDate and timeWhen the file was last modified
ModifiedByTextWho modified it
StatusChoice: Pending, Summarized, Failed, Skipped, DeletedWhere the file is in the process
SummaryMultiple lines of text (max 4,000)The short AI summary shown in the report
SummaryJsonMultiple lines of text (max length)The full AI answer, kept for later use
AttemptsWhole numberHow many times summarizing has failed
LastErrorMultiple lines of textThe last error message, for troubleshooting

After creating it, add a key (Keys → New key) on SpItemId. Why: a key stops two rows being created for the same file.

Table 3: FolderSummary

One row per area inside a LOB.

ColumnTypeWhat it's for
AreaText (primary column)The area name
LOBLookup → LOB ConfigWhich LOB it belongs to
DirtyYes/NoYes = a file in this area changed, so the overview needs rewriting
OverviewMultiple lines of textThe AI's 2–4 sentence overview of the area
ThemesJsonMultiple lines of textThemes, recent changes and open actions (from the AI)
FileCountWhole numberNumber of files in the area
SummarizedCountWhole numberHow many of them have summaries

Add a key on LOB + Area together.

Table 4: RunLog

One row each time a LOB is processed. Used for checking what happened.

Columns: LOB (Lookup), RunStartUtc (Date and time), FilesSeen, FilesSummarized, FilesFailed (Whole numbers), Outcome (Choice: Succeeded, Failed), ErrorText (Multiple lines of text).

Test Part 1: add one row to LOB Config by hand for a small test LOB: Enabled = Yes, LastSuccessfulRunUtc = 1900-01-01, BatchSize = 20, ReportFileName = Test.aspx. You'll use it in every test below.

Part 2 – WF2 Summarize file

Goal: given one row in DocCatalog, read that file from SharePoint, ask the AI for a short summary, and save it on the row.

Input: CatalogId (the ID of the DocCatalog row). Output: the row is updated to Summarized, Skipped, Pending (will retry) or Failed.

Steps

  1. New workflow named WF2 Summarize file. Choose the trigger for a workflow that is called by another workflow (child workflow). Add one text input: CatalogId.
  2. Add Dataverse "Get a row by ID", rename it Get_Row. Table: DocCatalog. Row ID: the CatalogId input.
  3. Add a Condition named Is_supported: check the file extension is one of pdf, docx, pptx, xlsx, txt, md.
    • If no: add "Update a row" → Status = Skipped, Summary = File type not summarized. Then add a Terminate action with status Succeeded.
    Why: files like videos or zip files can't be summarized. We still list them in the report, just without a summary.
  4. Add a Scope named Try. Put the next four actions inside it.
    Why: a Scope groups actions. If anything inside fails, we can catch the error in one place (step 9) instead of the whole workflow crashing.
  5. Inside Try: SharePoint "Get file content" using the file's ID or path from Get_Row. Rename it Get_File.
  6. Inside Try: "Run a prompt" (under AI capabilities). Rename it Summarize. Paste the prompt below, and give it the file as a document input. Set the output to JSON and paste the schema below.
  7. Inside Try: "Parse JSON". Content = the prompt's output. Schema = the same schema. Rename it Parse_JSON.
    Why: Parse JSON checks the AI really returned the fields we asked for. If it didn't, this step fails and we retry later instead of saving garbage.
  8. Inside Try: "Update a row" on DocCatalog (row ID = CatalogId):
    • Status = Summarized
    • Summary = body('Parse_JSON')?['summary']
    • SummaryJson = the prompt's whole output
    • LastError = empty
  9. Add a second Scope named Catch, after Try. Open its Settings → Run after and tick only has failed and has timed out. Inside it add "Update a row":
    • Attempts = add(outputs('Get_Row')?['body/rpt_attempts'], 1) (add one to the counter)
    • Status = if(greaterOrEquals(add(outputs('Get_Row')?['body/rpt_attempts'], 1), 3), 'Failed', 'Pending')
    • LastError = the error message
    In plain words: "add 1 to the failure count; if it has now failed 3 times, mark it Failed, otherwise leave it Pending so the next run tries again." (For a Choice column you may need to pick the option's number instead of typing the word.)
  10. Retry settings: on Get_File and Summarize, open Settings → Retry policy → Exponential, count 4.
    Why: if SharePoint or the AI is busy (error 429 "too many requests"), the action waits and tries again automatically.

The prompt (paste into "Run a prompt")

You summarize one document from the {LOB} line of business for a status report.
Use only the document. If something is not stated, return an empty string or empty list.
Return ONLY valid JSON matching the schema. No markdown, no HTML, no commentary.
summary: at most 80 words, plain language, what the document is and its main point.
key_points: at most 5 items, each under 20 words.
actions_or_risks: open actions, deadlines or risks stated in the document.

File: {FileName}  |  Folder: {Area} / {Breadcrumb}  |  Modified: {ModifiedUtc}
Document: {the file}

The words in { } are inputs: create them in the prompt and map them to fields from Get_Row.

The JSON schema

{
  "type": "object",
  "properties": {
    "title":              { "type": "string" },
    "doc_type":           { "type": "string", "enum": ["report","procedure","minutes","plan","data","other"] },
    "summary":            { "type": "string" },
    "key_points":         { "type": "array", "items": { "type": "string" } },
    "owner":              { "type": "string" },
    "decision_or_status": { "type": "string" },
    "actions_or_risks":   { "type": "array", "items": { "type": "string" } }
  },
  "required": ["title","doc_type","summary","key_points"]
}
Common mistake: using an agent node here instead of "Run a prompt". Summarizing one file needs no tools or searching; a prompt is cheaper, faster and gives more consistent results.
Test Part 2: add a DocCatalog row by hand for one real PDF in your test LOB (Status = Pending, Attempts = 0). Run WF2 with that row's ID. Check the row now says Summarized and has a sensible summary. Then try a .zip file and check it becomes Skipped.

Part 3 – WF3 Roll up area

Goal: write a short overview for one area, using only the saved file summaries (never the files themselves).

Input: FolderSummaryId. Output: the FolderSummary row gets an Overview and is marked not Dirty.

Why summaries and not files? An area might have hundreds of files. One line per file is small enough for the AI to read at once; hundreds of full files are not.

Steps

  1. New workflow WF3 Roll up area, child trigger, text input FolderSummaryId.
  2. Get a row by ID on FolderSummary. Rename it Get_Area. This tells us the LOB and the Area.
  3. List rows on DocCatalog, renamed List_Files:
    • Filter rows: this LOB, this Area, Status = Summarized
    • Select columns: rpt_filename,rpt_breadcrumb,rpt_modifiedutc,rpt_summary (only what we need; makes it faster)
    • Sort by: rpt_modifiedutc desc (newest first)
    • Settings → Pagination on, threshold 5000. Why: without it you only get the first page of rows.
  4. Select (Data operations), renamed Lines. From = List_Files value. Switch to text mode and use: 
    concat(item()?['rpt_breadcrumb'], ' | ', item()?['rpt_filename'], ' | ',
       formatDateTime(item()?['rpt_modifiedutc'],'yyyy-MM-dd'), ' | ', item()?['rpt_summary'])
    In plain words: turn each file into one line like Relays / 2026 | test-report.pdf | 2026-11-02 | Summary text…
  5. Condition: is the number of lines 60 or fewer? lessOrEquals(length(body('Lines')), 60)
    • Yes: "Run a prompt" (the roll-up prompt below) with all the lines joined into one text: join(body('Lines'), decodeUriComponent('%0A')) (%0A is a line break).
    • No: split the lines into groups of 60 with chunk(body('Lines'), 60), loop over the groups (concurrency 1), run the prompt on each group, collect the answers in an array variable, then run the prompt one last time over the collected answers.
    Why split at 60? It keeps each AI request small enough to be reliable. You can adjust the number later.
  6. Parse JSON on the prompt output, then Update a row on FolderSummary: Overview, ThemesJson, FileCount, SummarizedCount, and Dirty = No.

Roll-up prompt

You are given one-line summaries of files in the {Area} area of {LOB}.
Return ONLY JSON with these fields:
  overview: 2-4 sentences describing what this area contains
  themes: up to 5 short themes
  recent_changes: up to 5 items, newest first, mention file names
  open_actions: up to 5 open actions or risks
Use only the lines given.
Test Part 3: summarize 3–4 files in one area with WF2, create a FolderSummary row for that area by hand (Dirty = Yes), run WF3 with its ID, and check the Overview makes sense.

Part 4 – WF4 Render report

Goal: build the HTML report for one LOB from the saved data, and save the file. There is no AI in this workflow.

Input: LobId. Output: the report file in the Reports folder.

First: the escaping rule

Before putting any text into HTML (a file name, a summary), you must escape it. Otherwise a file called Q3 <draft> & notes breaks the page, because < and & have special meaning in HTML.

Wherever this guide writes E(something), use this full expression with something in place of x:

replace(replace(replace(replace(coalesce(x,''),'&','&amp;'),'<','&lt;'),'>','&gt;'),'"','&quot;')
In plain words: "if it's empty use blank text; then replace & with &amp;, < with &lt;, > with &gt;, and quote marks with &quot;." The & replacement must come first.

Steps

  1. New workflow WF4 Render report, child trigger, input LobId.
  2. Get a row by ID on LOB Config → rename Get_LOB.
  3. List rows on FolderSummary for this LOB, sorted by Area → rename List_Areas.
  4. List rows on DocCatalog for this LOB where Status is not Deleted. Select only the columns the report needs (rpt_area, rpt_breadcrumb, rpt_filename, rpt_fileurl, rpt_modifiedutc, rpt_status, rpt_summary). Pagination on. Rename List_Files.
  5. Count the files by status: add four Filter array actions on List_Files (Status = Summarized, Pending, Failed, Skipped). The count is length(body('Filter_Summarized')) and so on.
    Why: the report shows these counts at the top, so readers can see whether it covers everything.
  6. Select renamed Toc (table of contents), from List_Areas, text mode: 
    concat('<li><a href="#', concat('a-', replace(uriComponent(toLower(item()?['rpt_area'])), '%', '-')), '">',
       E(item()?['rpt_area']), ' (', item()?['rpt_filecount'], ')</a></li>')
    In plain words: one link per area, like Protection (42), pointing to that area's section further down the page. The a-… part turns the area name into a safe link ID.
  7. Initialize variable Sections, type Array.
  8. Apply to each over List_Areas. Settings → Concurrency control OFF.
    Important: if this loop runs in parallel, sections get mixed up or lost when they're added to the variable. This was one of the old bugs. Keep it one-at-a-time.
    Inside the loop:
    1. Filter array on List_Files where Area = the current area → rename Files_In_Area.
    2. Select renamed FileRows → one table row per file: 
      concat('<tr><td><a href="', item()?['rpt_fileurl'], '">', E(item()?['rpt_filename']), '</a></td>',
       '<td>', E(item()?['rpt_breadcrumb']), '</td>',
       '<td>', formatDateTime(item()?['rpt_modifiedutc'],'yyyy-MM-dd'), '</td>',
       '<td>', E(item()?['rpt_summary']), '</td></tr>')
    3. Append to array variable Sections → the whole section: a heading, the overview, and a table containing join(body('FileRows'), ''): 
      concat('<section id="', [same a-… ID as above], '"><h2>', E(area name), '</h2>',
       '<p class="ov">', E(overview), '</p>',
       '<table><thead><tr><th>File</th><th>Folder</th><th>Modified</th><th>Summary</th></tr></thead>',
       '<tbody>', join(body('FileRows'), ''), '</tbody></table></section>')
  9. Compose renamed Html: paste the template below. The parts in @{ } are filled in automatically; replace each E(…) with the full escape expression.
  10. Save the file to the Reports folder with the name from ReportFileName. First use "Get file metadata using path" to check whether the file exists; if it does use Update file, if not use Create file.
    Why .aspx? SharePoint downloads .html files instead of opening them. An .aspx file opens in the browser, but only if the connection used in this step belongs to a site owner. The other option is to email or post the .html file to Teams.
  11. Update a row on LOB Config: ReportDirty = No, LastReportUtc = utcNow().

The HTML template (paste into the Html Compose)

<!DOCTYPE html>
<html lang="en"><head><meta charset="utf-8">
<title>@{E(LOB name)} – Content report</title>
<style>
body{font:14px/1.5 Segoe UI,Arial,sans-serif;margin:24px;color:#222}
.banner{background:#f3f6f9;border:1px solid #d0d7de;padding:12px 16px;border-radius:8px}
.warn{color:#b35900}
table{border-collapse:collapse;width:100%;margin:8px 0 24px}
th,td{border-bottom:1px solid #e5e7eb;padding:6px 8px;text-align:left;vertical-align:top}
th{background:#fafafa}
.ov{max-width:900px}
</style></head><body>
<h1>@{E(LOB name)} – Content report</h1>
<div class="banner">Generated @{formatDateTime(utcNow(),'yyyy-MM-dd HH:mm')} UTC ·
 @{TotalFiles} files · @{Summarized} summarized · @{Pending} waiting ·
 <span class="warn">@{Failed} failed</span> · @{Skipped} not summarizable</div>
<h2>Contents</h2><ul>@{join(body('Toc'),'')}</ul>
@{join(variables('Sections'),'')}
</body></html>
Test Part 4: run WF4 for your test LOB. Open the report: every area from FolderSummary should appear, every summarized file should be listed, and the counts at the top should match DocCatalog. Rename one test file to include & and <, re-run, and check the page still looks right.

Part 5 – WF1 Process LOB

Goal: for one LOB, find files that changed since the last successful run, record them in DocCatalog, then call WF2, WF3 and WF4. This is the main workflow and replaces the old "scan everything" approach.

Input: LobId.

Part A – Setup

  1. New workflow WF1 Process LOB, child trigger, input LobId.
  2. Get a row by ID on LOB Config → rename Get_LOB.
  3. Compose renamed RunStart = utcNow().
    Why: we record when this run started. If the run succeeds, this becomes the new watermark. We use the start time, not the end time, so files changed during the run are picked up next time.
  4. Compose renamed Since: 
    formatDateTime(addMinutes(outputs('Get_LOB')?['body/rpt_lastsuccessfulrunutc'], -10), 'yyyy-MM-ddTHH:mm:ssZ')
    In plain words: "the watermark minus 10 minutes, in the date format SharePoint expects." The 10-minute overlap is a safety margin. Files seen twice are harmless, because step 6 checks whether they really changed.

Part B – Find and record changed files (inside a Scope named Try)

  1. SharePoint "Get files (properties only)" → rename Get_Files:
    • Library: Documents
    • Limit entries to folder: the LOB's FolderPath from Get_LOB
    • Include nested items: Yes (otherwise it ignores sub-folders)
    • Filter Query: Modified ge '@{outputs('Since')}' and FSObjType eq 0
      Means: "modified on or after Since, and is a file, not a folder." If SharePoint rejects FSObjType, delete that part and later skip items where {IsFolder} is true.
    • Settings → Pagination on, threshold 20000.
  2. Apply to each file in Get_Files (Settings → Concurrency 10). Inside:
    1. Compose Parts = split(item()?['{Path}'], '/')
      Means: cut the folder path into pieces. Shared Documents/Transmission/Protection/Relays/ becomes ["Shared Documents","Transmission","Protection","Relays",""]. Position 0 is the library, 1 is the LOB, 2 is the Area.
    2. Compose Area = if(greater(length(outputs('Parts')), 3), outputs('Parts')[2], 'General')
      Means: take piece number 2 as the area. Files sitting directly in the LOB folder (no area) go into an area called "General".
    3. Compose Breadcrumb = join(take(skip(outputs('Parts'), 3), max(0, sub(length(outputs('Parts')), 4))), ' / ')
      Means: join every folder below the area with " / ", e.g. Relays / 2026 / Q3.
    4. List rows on DocCatalog where rpt_spitemid eq @{item()?['ID']}, row count 1 → rename Find_Existing. (Do we already have a row for this file?)
    5. Condition: empty(outputs('Find_Existing')?['body/value'])
      • Yes (new file): Add a new row to DocCatalog with SpItemId, LOB, Area, Breadcrumb, FileName ({Name}), FileUrl ({Link}), ETag (item()?['@odata.etag']), ModifiedUtc, ModifiedBy, Status = Pending, Attempts = 0.
      • No (known file): another Condition. Is the saved ETag different from item()?['@odata.etag']? If yes, the file really changed: Update the row with the same fields, Status = Pending, Attempts = 0. If no, do nothing.
    Folder positions: the numbers 2 and 3 above assume Library/LOB/Area/…. If your LOB folders are one level deeper (e.g. Library/Business/LOB/Area), add 1 to each of those numbers.
  3. Mark changed areas as Dirty. Add a Select ChangedAreas over Get_Files that outputs each file's area (same expression as step 6.2 but using split(item()?['{Path}'],'/') directly). Then a Compose DistinctAreas = union(body('ChangedAreas'), body('ChangedAreas')) (removes duplicates). Loop over DistinctAreas (concurrency 1) and for each one add or update the FolderSummary row for this LOB + Area with Dirty = Yes.
  4. If any files were found (greater(length(body('Get_Files')?['value']), 0)), update LOB Config: ReportDirty = Yes.

Part C – Summarize, roll up, render (still inside Try)

  1. List rows on DocCatalog: this LOB, Status = Pending, sorted by ModifiedUtc ascending, row count = BatchSize → rename Pending_Files.
    Why a batch size? On the first run there may be thousands of Pending files. Limiting each run to e.g. 100 keeps runs short and costs predictable; the rest are picked up by the next runs.
  2. Apply to each pending file (concurrency 5) → Run a child workflow: WF2, passing the row's ID as CatalogId.
  3. List rows on FolderSummary: this LOB, Dirty = Yes → Apply to each (concurrency 3) → Run a child workflow: WF3 with the row's ID.
  4. Get the LOB Config row again (it may have changed). If ReportDirty = Yes → Run a child workflow: WF4 with LobId.
  5. Update LOB Config: LastSuccessfulRunUtc = outputs('RunStart'). This is the last step inside Try.
  6. Add a RunLog row with Outcome = Succeeded and the counts.

Part D – Handle failures (Scope named Catch)

  1. Add a Scope Catch after Try, with Run after = has failed and has timed out. Inside, add a RunLog row with Outcome = Failed and ErrorText = string(result('Try')).
    Do not update the watermark in Catch. Because the watermark only moves at the end of a successful Try, a failed run is simply repeated next time and no file is missed.
Test Part 5: run WF1 for your test LOB (watermark 1900-01-01). Check that DocCatalog now has one row per file, files get summarized up to BatchSize, and a report is produced. Then: edit one file in SharePoint, run WF1 again, and confirm only that file was re-summarized (check RunLog counts).

Part 6 – WF0 Orchestrator

Goal: every 30 minutes, start WF1 for each enabled LOB. It does nothing else.

  1. New workflow WF0 Orchestrator with a Recurrence trigger every 30 minutes. In the trigger's Settings turn Concurrency control on and set the limit to 1.
    Why: if one run takes longer than 30 minutes, the next one waits instead of running at the same time and processing the same files twice.
  2. List rows on LOB Config where rpt_enabled eq true.
  3. Apply to each LOB (Settings → Concurrency 3) → Run a child workflow: WF1 with the LOB's ID.
  4. On anything after the child call, set Run after to include has failed, so one failed LOB doesn't stop the others.
Test Part 6: enable two LOBs, turn WF0 on, wait for one run, and check RunLog has a row for each LOB.

Part 7 – WF5 Weekly reconcile

Goal: find files that were deleted from SharePoint. WF1 can't see deletions, because it only asks "what was modified?", and a deleted file isn't there to be asked about.

  1. New workflow WF5 Weekly reconcile, Recurrence trigger weekly (e.g. Sunday 2 AM).
  2. For each enabled LOB: Get files (properties only) with no date filter, nested items Yes, pagination on. Add a Select SpIds that outputs just item()?['ID'].
  3. List rows on DocCatalog for the LOB where Status is not Deleted (select only rpt_spitemid, pagination on).
  4. Filter array on those rows where not(contains(body('SpIds'), item()?['rpt_spitemid'])). Means: "rows whose file is no longer in SharePoint."
  5. For each of them: Update a row Status = Deleted, mark its area Dirty, and set the LOB's ReportDirty = Yes.
Test Part 7: delete a test file in SharePoint, run WF5 manually, then run WF1. The file should be gone from the report.

Part 8 – First run and go-live

The first run (backfill)

  • Each new LOB starts with watermark 1900-01-01, so its first run records every file as Pending.
  • Summaries then fill in at BatchSize files per run. Until they're done, the report shows a "waiting" count at the top. This is expected.
  • To finish faster, run once overnight with BatchSize 500 and the WF2 loop concurrency at 10.

Settings to double-check

  • Everything is in the solution, using connection references (for SharePoint and Dataverse) and environment variables for the site URL and library name.
  • Retry policy Exponential (4) on every SharePoint and AI action.
  • Every action uses Copilot Credits. Processing only changed files is what keeps the cost low.

Go-live checklist

  • One LOB fully backfilled; report file count matches the number of files in its SharePoint folder.
  • Editing one file re-summarizes only that file.
  • A file 4 folders deep appears in the right area with the right breadcrumb.
  • A file name containing & and < displays correctly.
  • A broken file ends up Failed after 3 tries, is shown in the count, and the report still builds.
  • A deleted file disappears after WF5 runs.
  • Stopping a run halfway does not move the watermark, and the next run catches up.
  • A normal team member can open the report in the browser (it doesn't download).
  • Remaining LOBs enabled one at a time; the old 10 flows turned off.
