LOB SharePoint HTML Reports – Architecture

Copilot Studio (Microsoft Copilot harness) · one HTML report per line of business · see the full rebuild spec for node-by-node build steps.

In one sentence: scheduled workflows process only the files that changed in each LOB, summarize each file once into Dataverse, and render each LOB's report from stored summaries with a fixed template. No retrieval (RAG) and no AI-written HTML.

Why the old design failed

  • RAG can't produce a complete report. Retrieval returns the top few chunks, so a report over hundreds of folders silently leaves most content out and changes from run to run.
  • Full scans every run hit the 100-second agent-flow limit, SharePoint throttling (600 calls/min) and model context limits.
  • The AI writing HTML runs into output-token limits and truncates the report; unescaped characters break it.

Components

WorkflowTriggerResponsibility
WF0 OrchestratorRecurrence, 30 min, concurrency 1Calls WF1 once per enabled LOB
WF1 Process LOBChildLists files modified since the LOB's watermark, queues changed files, calls WF2 → WF3 → WF4, then moves the watermark only on success
WF2 Summarize fileChildOne prompt per file → validated JSON summary; retries, then marks Failed
WF3 Roll up areaChildArea overview from stored file summaries only (batched over 60 files)
WF4 Render reportChildSelect/Join + fixed template → one escaped, well-formed HTML file per LOB
WF5 Weekly reconcileRecurrence, weeklyMarks deleted files so reports stay accurate

Data model (Dataverse)

TableGrainPurpose
LOB Config1 per LOBFolder path, enabled flag, watermark, batch size, report file name, dirty flag
DocCatalog1 per filePath, Area, breadcrumb, ETag, status (Pending/Summarized/Failed/Skipped/Deleted), summary JSON
FolderSummary1 per LOB + AreaSection overview, themes, coverage counts, dirty flag
RunLog1 per LOB per runCounts, outcome, errors, duration

Design rules

  1. Per-LOB isolation: each LOB has its own child run and watermark; one failure never blocks the others.
  2. Incremental only: filter on Modified ge watermark − 10 min (index the Modified column); ETag decides whether to re-summarize.
  3. Summarize once: unchanged files cost nothing on later runs; a per-run batch cap drains backlogs predictably.
  4. Deterministic rendering: the AI never writes HTML; every inserted value is escaped; the append loop runs with concurrency 1.
  5. Trustworthy output: each report opens with a coverage banner (total · summarized · pending · failed · skipped).
  6. Safe failure: Try/Catch scopes; the watermark only moves on success, so a failed run is retried in full.

Publishing note

SharePoint Online downloads .html files rather than rendering them. Save reports as .aspx with a site-owner connection, or deliver the .html as a Teams/Outlook attachment.
